## Gaps (known, deliberate or waiting on Dev)

- **Clean-up:** there is no delete API, so every written fake record stays on staging and is reported as
  "left behind" (BQ-10).
- **Token format leniency:** the facade accepts the token without "Bearer" or with lower-case "bearer". Not tested
  until Dev says whether that is intended (BQ-17).
- **Duplicates:** duplicate user IDs or field names return duplicate items; de-duplication is not asserted (BQ-19).
- **Wrong HTTP method:** `POST` on the health endpoint returns a 502 page instead of 405; informational only (BQ-20).
- **Maximum request size (413)** and a `fields` maximum for bulk read are not documented, so not tested (BQ-05).
- **Not-ready health (503)** cannot be triggered safely on staging.
- **Phone length limits (8/15 digits)** cannot be tested with approved 10-digit test phones; only the invalid-phone
  case is planned (AISLE-NRM-003, BQ-03).
- **Encryption proof:** DB tests only show a value is not stored readable. Proving encryption needs the storage
  format from Dev (BQ-04).
- **Per-user isolation:** today any user ID can be read or written with the same token (BQ-07).
- **Out of scope by design:** PII-service signing, caller IDs, per-caller permissions and tenant selection — Aisle
  handles these internally and QA tests only the facade.
