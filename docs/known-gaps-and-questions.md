# Known Gaps, Assumptions and Questions for the Backend Team

Source of truth: **PII Service API Integration Guide** (13 pages, `PII.pdf`). Everything below is either
missing from, or ambiguous in, that guide. IDs are referenced from test annotations
(`blocked` / `assumption` in the HTML report), so a reviewer can go from a report entry straight to this list.

Legend: **Blocks** = tests marked `fixme` (never "passed") until answered. **Tolerant** = the test currently
accepts a small closed set of outcomes and should be tightened once answered.

## 2. Assumptions made (documented, reversible)

| ID   | Assumption                                                                                                                                                                                                                       | Where                      |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| A-01 | The `data` field of error envelopes is `null` (as in the guide's error example), except readiness 503.                                                                                                                           | `expectError`              |
| A-02 | Compact JSON (`JSON.stringify`) is an acceptable wire format. The server hashes the bytes it receives, so any byte-exact encoding works. Non-ASCII is sent as UTF-8 (Python's example would escape as `\uXXXX`); both are valid. | `serializeBody`            |
| A-03 | Retrying is safe only for read-only endpoints on 503 (checklist item 9). Writes/creates/promote/revoke are never retried (idempotency undocumented).                                                                             | `endpoints.ts` `retrySafe` |
| A-04 | A fresh `X-Request-Id` is generated per retry attempt (checklist item 6).                                                                                                                                                        | `BaseApiClient.execute`    |
| A-05 | `expires_at` is within `PII_CLOCK_SKEW_TOLERANCE_SECONDS` (default 120 s) of `now + ttl`.                                                                                                                                        | PII-TR-001                 |
| A-06 | Revoking an already-revoked key returns 404 `FREE_TEXT_KEY_NOT_FOUND` (derived from the error table: "Key is missing, revoked, or not owned").                                                                                   | PII-FT-004                 |
| A-07 | Authorization is evaluated before ownership lookup (restricted caller gets 403, not 404, on another caller's mapping).                                                                                                           | PII-AZ-009/010/011         |
| A-08 | The documented _development_ limits (batch 50, TTL 300–604800, search default 10) apply unless overridden per environment via env vars.                                                                                          | `.env.example`             |

## 4. Out of scope (Milestone 2)

Interception of encryption/decryption inside normal Aisle API flows. No Aisle integration APIs are
documented, so none are implemented. The framework is extensible for them (see `framework-architecture.md` §7).
