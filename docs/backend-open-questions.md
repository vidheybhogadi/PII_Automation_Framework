# Backend open questions — Aisle PII facade

Architecture under test: **QA automation → Aisle PII facade (Bearer token) → PII service → PII DB**.

Behaviour below was checked against the real staging facade (`https://testa2.aisle.co/V1`) on
**2026-09-29**. "Observed" means we saw it on staging; it is not a confirmed contract until Dev answers.

How questions affect tests:

- A test that cannot run meaningfully without an answer, access or data is **Blocked** (never passed or failed),
  with the question ID as the reason.
- A test that runs on observed behaviour cites the question, so the expectation can be confirmed or corrected.
- A feature Dev confirms as unsupported becomes **Not Applicable**.
- `(Q1)`…`(Q28)` refer to the numbered question list QA agreed to send to Dev.

**Status key:** Open = waiting for Dev · Observed = staging behaviour recorded, needs confirmation.

## Already answered by staging behaviour (kept for traceability)

- Made-up user IDs are accepted (so QA generates its own run-unique users).
- The tenant is always `aisle`, set by the facade.
- A user with no saved value → 404 `PII_NOT_FOUND`; a bulk read where any requested user has no value →
  404 for the whole request.
- NAME is trimmed and runs of inner spaces are collapsed; capitals are kept. Field names are case-insensitive.
- First save of a field → 201; saving again (same or different value) → 200.
- Broken JSON → 400 `{"status":false,"error":"Invalid JSON","message":"Request body must be valid JSON"}`.
- Missing / wrong / malformed token → 401 with an empty body.
